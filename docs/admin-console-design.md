# ADMIN 管理端与客户端按需绑定：设计草案

状态：2026-10-23 的设计记录。下文的能力缺口和候选路由保留了设计开始时的基线，不是当前 API 清单，也不是生产部署授权；网关仍是单实例合成预览。

## 首个实现切片

- 已实现独立本地管理员认证、真实状态/审计查询、带版本确认的策略修改/身份禁用/绑定撤销，以及配置草稿静态校验；准确路由见 [管理 API](admin-api.md)，操作流程见 [管理控制台](admin-console.md)。
- 已实现本人获准服务状态控制工具、专用鉴权绑定 API 与私有文件 CLI 的合成本机纵切，无需个人绑定网页。当前用代次/CAS 核对状态，不提供持久请求 ID 回执；准确契约见 [客户端绑定](client-binding.md)。
- 在线用户创建、网关 token 在线发行/轮换、服务拓扑迁移与应用仍未实现。配置校验不保存、不应用、不重启；原生 AI 客户端安全输入与远程生产绑定未验证。
- 第 9 节仅是历史路由提议，不能直接照其调用。当前管理端采用 snapshot/mutate 等实测接口；当前绑定 API 使用 services/credentials，而非尚未实现的 requests 挑战/回执协议。

## 1. 产品决定

- 管理员先配置 **MCP 服务**、用户入口身份和明确工具策略，颁发网关 token；用户只配置这个入口。用户所称上游对应代码 `System`/downstream，界面统一叫“MCP 服务”。
- 用户需要某服务而缺少服务凭据时，网关给客户端机器可读的待办；客户端引导用户安全提供凭据，**后台自动绑定到入口 token 对应身份与指定服务**。不是管理员必须手工代填，更不是用户必须另外打开绑定页。
- 网关 token 与服务 token 是两种不同凭据。前者只认证网关身份，不能直接转发作为后者；服务凭据不能改变身份、服务地址或工具授权。
- `/account` 保留为默认关闭的合成兼容预览，不再作为主产品路径，也不改名冒充 ADMIN。
- 不先做大 IAM、租户计费、花哨图表或假数据看板。先把服务接入、授权边界、真实状态、凭据补齐闭环做清楚。

## 2. 两个平面、两个角色

| 能力 | ADMIN 管理平面 | 普通 MCP 客户端 |
|---|---|---|
| 服务地址、认证头模式、网络允许列表、共享配额主体 | 配置/校验/发布（分阶段交付） | 不可修改，不接受用户指定任意 URL |
| 用户、入口 token 生命周期、工具白名单 | 管理；高风险操作确认与审计 | 仅使用本人入口，不能自报身份或申请即获权 |
| 服务凭据 | 查看绑定元数据、撤销；默认不可回读秘密 | 安全提交/替换/撤销本人绑定 |
| 运行诊断 | 跨获授权管理范围读取脱敏状态 | 仅本人获准服务状态 |
| 策略 | 明确完整工具名白名单，无通配 | 绑定成功也不增加权限 |

当前库级 `Identity` 参数不是远程鉴权。新增 ADMIN 必须另建可验证的管理员认证/会话与授权边界；普通网关 bearer 不能登录管理端。MVP 只需单一管理员角色 + 普通用户，不引入复杂角色树。管理监听/路由与数据平面明确隔离；浏览器会话需 CSRF/Origin 防护、到期、重认证和独立限额。此处是待设计实施条件，不宣称已有安全管理 API。

## 3. 导航与首用体验

顶部常驻：实例/环境、“合成预览”标识、持久/内存模式、当前运行版本、配置版本与待重启提示。左侧六项：

| 页面 | 首屏与主要操作 | 首次/空状态 |
|---|---|---|
| **概览** | 服务/身份配置数；发现可用与失败摘要；待处理配置；审计容量、未知结果、拒绝摘要 | 无服务：“先添加 MCP 服务”；无数据：“尚未采集”，绝不画虚假曲线 |
| **MCP 服务** | 稳定 ID、展示名（新字段）、固定端点、Bearer/raw/API-key 模式、头名、网络策略、配额主体；工具发现与安全错误 | 未检查/待凭据/已发现/发现失败分开；添加→保存草稿→校验，测试连接必须明确使用哪个合成身份 |
| **用户与入口 token** | 身份、禁用状态、入口代次/到期/撤销；新建与颁发（待实现）、替换/撤销；本人各服务绑定状态 | 尚无身份：创建合成用户；生成的入口秘密仅安全交付一次，表格永不回显 |
| **工具与授权** | 按服务看已发现工具；按用户查看“明确允许 / 当前可见 / 不可用原因”；保存白名单差异 | 无目录不能当作无权限；允许项可先配置，标记“尚未发现”，不捏造 schema |
| **运行与审计** | 发现/调用安全失败码、阶段、耗时、未知结果；拒绝摘要单列；容量与归档状态 | 没有历史不是零错误；注明范围、时间窗、重启归零/归档缺口 |
| **配置与维护** | 草稿/校验/运行差异、应用资格、重启计划；离线维护说明 | 无变更显示已同步；不可执行项明确原因，不放置假成功按钮 |

服务详情用“连接配置 / 工具目录 / 身份绑定摘要 / 诊断”四页签。绑定只呈现状态、代次、到期和最近安全诊断，不呈现 token。服务健康不能用一个用户发现成功代表所有用户，须显示观察时间和身份范围。

首用顺序：添加服务草稿 → 校验配置 → 创建合成身份/入口（当前先用受信离线引导）→ 明确授权 → 客户端连接 → 按需提供服务凭据 → 定向发现 → 列出可见工具。尚未实现的步骤标为不可用，不伪装端到端可运行。

## 4. 实际能力与缺口

| 源码/文档证据 | 现在有 | 需要补齐 |
|---|---|---|
| `config.go`, `network_policy.go`, `cmd/gateway/onboarding.go` | 固定服务配置、三种认证头模式、网络限制、离线 check-config | 管理读模型、配置草稿/版本、在线管理鉴权；展示名与启停不是现有字段 |
| `identity.go`, `entry_maintenance.go`, `maintenance_store.go` | 绑定/策略版本、禁用、撤权；受信库接口；离线入口替换/撤销 | 用户增删与入口颁发、在线管理生命周期；不能把库接口直接暴露 |
| `account_identity.go`, `account_http.go` | 本人绑定元数据、CAS 替换/撤销、定向发现；有限期入口验证 | 客户端绑定挑战/安全投递通道/查询回执；ADMIN 不是 account API 扩展皮肤 |
| `gateway.go` | 按身份发现并发布授权目录，调用独立校验 | 缺凭据时没有业务工具；现有调用拒绝不是结构化绑定提示，需要独立服务准备能力 |
| `persistence.go` | 加密服务凭据、入口摘要、持久撤权、拓扑匹配 | 安全拓扑迁移；生产秘密托管/备份反回滚；不能称为生产 vault |
| `audit*.go`, `rejection.go`, `failures.go` | 有界元数据审计、固定分类、未知结果；进程内拒绝摘要 | 管理查询授权、跨事件聚合、完整管理员操作审计、历史指标存储 |

现有上限为 16 个服务、64 个配置用户（`newGateway`）；界面校验须尊重当前约束，不宣传无限扩展。

### 配置保存、校验、应用、重启不是同一件事

1. **草稿**：脱敏配置版本 + 基础版本，不改变运行实例；服务秘密不混入可导出配置。
2. **校验**：静态 schema/名称/网络/头名/配额检查。现有 `check-config` 不联网、不读写数据库，成功不表示服务可用或存储可重开。
3. **检查应用资格**：对比运行与持久拓扑、授权版本、入口代次；显示影响用户/目录与停机要求。网络测试独立、显式且有界，不以业务写工具“测试连通”。
4. **应用**：只发布已校验的指定版本，CAS 防止覆盖他人修改；持久状态权威，不从旧配置恢复 token/策略。未实现管理执行器前只允许草稿与导出脱敏差异，不能标记已应用。
5. **重启/验收**：普通配置当前不热更新；启动发现可能部分失败，需分别呈现“进程已启动 / 存储验证通过 / 服务发现结果”。失败保留可诊断状态，不循环重启、不自动重试业务调用。

**关键限制：** SQLite 拓扑摘要涵盖完整 `systems` 与身份映射；新增用户/服务、改变服务端点/认证模式等不是“保存后重启”即可，会因拓扑不匹配拒绝打开。当前标记“需要尚未实现的拓扑迁移，不能应用”。后续需单独、显式、可验证的离线迁移；禁止删除 DB、重做 `init-db` 或导入旧数据库绕过撤权。内存模式重启会重置动态状态，必须显著警告；根密钥轮换、入口维护、审计归档仍走现有停服流程。配置回退也不能等同权限/数据库回滚。

## 5. 客户端按需绑定闭环

### 避免“缺工具就永远触发不了绑定”的死路

当前缺凭据不会发现该服务工具，`Call` 前置判断返回 `ErrDenied`。不能虚构业务工具 schema，也不能放宽目录成员校验。

提议新增最小控制能力（名称/载荷尚非已发布协议）：列出**本人明确获准使用**的服务状态，以及“准备连接某服务”。它不执行业务、不接受凭据字段、不接受用户/tenant/端点字段。只以服务固定 ID 为参数，返回公开安全状态与下一步。管理员尚未授权的服务不暴露详情、不索取秘密。缺凭据的第一次引导由此触发，而不是依赖不存在的业务工具。需预留控制工具命名空间、防止与服务工具冲突，并单独设计其访问权限。

流程：有效入口认证 → 检查明确策略 → 读取绑定状态 → 若需要，签发短期单用途挑战 → 客户端解释请求来源/服务并允许取消 → 安全通道提交 → 绑定事务提交 → 本人该服务定向发现 → 返回绑定回执与发现结果 → 客户端重新 `tools/list` → 用户继续原任务。

挑战由服务器绑定到 tenant/principal、入口代次、服务、预期绑定代次、过期时间；普通模型只见不具有写权限的 request ID。不能凭 ID 单独提交/读取他人状态，仍须可信通道认证与最终身份/策略复验。一次性消费、防重放、限额、并发 CAS、日志脱敏必须在任何真实凭据试点前完成。重复提交先查回执，不能把响应丢失当作未保存。

示意安全返回（产品契约草案，不是 MCP 标准错误码）：

```json
{
  "code": "credential_required",
  "service_id": "crm",
  "binding_state": "missing",
  "request_id": "opaque-non-authorizing-id",
  "submission": "secure_channel_required",
  "business_dispatched": false,
  "retry_business": false
}
```

### 状态机：凭据、发现、业务结果是三个维度

| 观察/状态 | 客户端动作与转换 |
|---|---|
| `missing` | 无凭据；明确请求用户提供→安全提交→`saved`，取消则保持 missing |
| `expired` | 仅本地已知 expires_at 到期；替换时 CAS→saved；不据提供方 401 猜过期 |
| `revoked` | 本地已撤销；不静默复活。用户明确重新连接且当前策略允许时创建新一代；若管理策略禁止则拒绝 |
| `provider_rejected` | 401/403 的诊断覆盖层，不改写已存绑定为 revoked/expired。401 提示核对凭据，403 提示权限范围；禁止反复索要 token 当作万能修复 |
| `saved` + `discovery_pending/failed/ready` | 保存成功与目录可用分开。失败保留绑定回执，只在明确操作下重做只读发现，不盲目重复绑定；ready 后仍只发布交集 |
| `outcome_unknown` | 绑定提交响应丢失：查请求回执/代次；业务已出站而超时/断线：保留未知结果，**绝不自动重放**，先向提供方核对 |
| 入口过期/撤销/禁用，或策略拒绝 | 不进入服务凭据流程；先恢复合法网关入口/管理员授权，秘密不能绕过这些阻断 |

绑定不自动恢复旧业务调用。只有明确证明业务尚未派发的待办可在重新授权/参数校验后由客户端继续；MVP 优先让用户明确继续。协议多轮重试也不能当作已出站业务的幂等保证。

## 6. 安全提交选择与协议兼容缺口

**禁止默认让用户把服务 token 粘贴到聊天、普通工具参数、elicitation 表单、URL 查询、shell argv、日志或可导出配置。** 输入框显示为密码不代表秘密没有进入模型上下文。

可满足“不另开绑定页”的候选通道，按实测能力选择：

1. **客户端原生安全凭据 UI/secret store**：宿主确认目标，秘密经专用受保护通道投递网关；模型只见回执。需要验证宿主接口、秘密隔离、授权、删除语义及目标客户端支持，不能仅凭 MCP 协议存在就承诺可用。
2. **本机安全辅助程序/CLI**：客户端给出不含秘密的挑战说明；用户显式在可信本机无回显提示中输入，或选择 owner-only 私有凭据文件；辅助程序以经过验证的网关地址与本人认证直接提交专用绑定通道。秘密不经模型、命令行参数或工具结果。无需网页，较便携但多一步本机交互，需要安装/信任与网关 TLS/端点固定验证；当前仓库尚无此提交命令或通道。
3. **URL elicitation / 提供方 OAuth**：标准化的可选带外交互，客户端获知完成状态而非秘密；需要额外用户同意，不能将其作为“无需另外打开绑定页”的完成标准。当前没有 OAuth 实现，不在本轮强加。

如果目标客户端和部署环境均无安全通道，返回 `secure_channel_unavailable`，清楚说明“已识别需补凭据，当前客户端尚不能安全完成”；不偷偷降级成明文聊天，不强迫用户去 `/account`，也不要求管理员代收秘密。后台绑定本身可实现，缺口是安全交付能力和客户端集成，并非协议全面禁止 token 绑定。

**官方依据（2026-10-23 核对）：** [MCP 2026-07-28 Elicitation](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation) 禁止 form 模式索取密码/API key/access token；敏感 elicitation 使用 URL 模式，且必须匹配客户端声明能力。URL 流不替换网关 bearer。此版能力随请求 `_meta` 发送，多轮交互载于 `inputRequests/inputResponses`；旧版协商路径不同，应按协议版本适配而非硬编码。 [Go SDK 客户端说明](https://go.sdk.modelcontextprotocol.io/client/#elicitation) 说明 handler 与 URL 能力声明要求，以及新协议多轮路径；仓库依赖固定为 v1.7.0。SDK 有能力不表示网关接入完成，也不证明 Codex/其他 GUI 客户端支持。上述原生/CLI 投递是额外受保护通道设计，不冒称标准 form elicitation。实际目标客户端支持必须用合成凭据单独验收。

## 7. 看板只能显示有证据的数据

- 可先接受信库读模型：配置服务/用户数；本人/管理范围绑定元数据；授权工具快照；`AuditStatus` 容量、Dropped、Pending、Unfinished、ArchivedUnfinished；`RejectionStatus` 固定类别 Count/Last/Started/Saturated。暴露到管理 UI 仍需新鉴权读接口。
- 审计里确有发现/调用时间与耗时、安全类别和 `ToolIsError`，但当前无现成趋势服务。可做明确覆盖区间内的事件列表；“成功”需区分传输完成和工具业务错误。
- HTTP 拒绝数和操作拒绝数单位不同，不能相加当请求总量；拒绝摘要重启清零，未覆盖所有 SDK/宿主拒绝。审计容量有界/可归档，不能据保留样本宣称全量成功率。
- 发现状态是最近一次、按身份观察，不是实时 uptime。服务连通性不能由配置有效推断。
- 不先显示 QPS、p95、DAU、全站成功率、SLA 或成本：缺分母/采集/历史窗口时显示“尚未采集”，不是 0。审计未知结果单列，绝不归入失败后自动重试。

## 8. 小步 MVP 与验收门槛

1. **管理信息架构与只读真数据**：独立管理员边界后做六页骨架与真实状态、空状态；服务配置草稿+静态校验+差异，不假装可应用。缺客户端安全通道不阻塞这些工作。
2. **合成凭据绑定纵切**：选一个实际可验证的原生或本机安全辅助通道；做服务准备控制能力、身份绑定挑战、CAS/回执、定向发现与重新列举；证明模型/日志从未收到秘密。暂不做生产 OAuth。
3. **有限管理写入**：先包装已有策略/撤销能力并记录管理员主体与版本；入口颁发与交付、用户/服务拓扑迁移、受控应用/重启分别补足，不能用 UI 代替存储语义。每类新增变更经明确实施授权后落地。

验收必须覆盖：无服务/无用户/无策略；缺/过期/撤销凭据；401 与 403；取消和重复提交；双客户端旧代次冲突；跨身份/跨服务挑战；入口中途过期/撤权；保存成功但发现失败；响应丢失后查状态；超时结果未知不重放；绑定后无额外授权；持久重启仍撤权；配置校验不联网；拓扑不匹配不破坏 DB；管理端普通 bearer 拒绝；看板明确重启/历史覆盖边界。SDK 测试与实际目标客户端 UI 测试分别报告，不互相代替。

未决但不阻塞只读管理设计：首个目标客户端及其安全输入能力；首个可用提交通道；生产管理员认证与秘密托管方案。本草案不为这些缺口编造支持或授权。

## 9. 第一可交付前后端契约（提议，实施时以测试锁定）

用户已于 2026-10-23 05:24:59 UTC 指示开始；本节给实施拆分，不把候选端点描述成现有 API。

**先做合成管理预览：** 默认关闭、仅回环；管理员秘密来自独立 owner-only 文件，不能复用用户入口 token；管理请求使用显式 Authorization bearer、浏览器仅内存保留，退出清除，不放 URL/storage。服务端严格固定 Host/Origin、方法、JSON 大小、凭据单值与 constant-time 验证、无缓存、无第三方脚本、限流；非管理员/错误凭据均拒绝。权限在服务端核验，不是前端隐藏按钮。生产会话/远程暴露另行安全设计，不因此扩大当前网络边界。

| 路由提议 | 语义/响应要点 |
|---|---|
| `GET /admin` 与固定 assets | 六页壳；未认证不加载业务数据；可显示登录而非泄露实例详情 |
| `GET /admin/api/overview` | `observed_at`, `mode`, `counts`, `audit_status`, `rejection_status`, `limitations`；数据缺失用 null/明确原因，不补 0 |

首期草稿可仅保存在当前浏览器内存，明确“未提交，刷新会丢失”；校验成功不显示“保存成功/已生效”。不要复用含用户 bootstrap 秘密的原始 Config 直接 JSON 输出。校验服务片段应由服务端与受信基线组合验证；浏览器不取回 token 来凑齐配置。不要新增假 `apply`/`restart`/用户创建按钮。版本冲突 409；失败统一安全 code，凭据不回显、下游错误原文不透传。统计取不到的运行数据应带 `availability` 而非猜测。

客户端绑定后续最小独立面：`GET /binding/api/services`（本人获准服务状态），`POST /binding/api/requests`（service_id、expected_generation，无秘密），`GET /binding/api/requests/{id}`（本人回执），`POST /binding/api/requests/{id}/submit`（只让受保护辅助程序提交 credential/可选到期）。这些是**候选专用 HTTP 通道，不是普通 MCP 工具参数**。同一个有效网关 bearer 确定身份；请求不可指定 tenant/principal/端点。提交要求挑战、入口代次、绑定代次复验，单次事务回执，不靠自动重试完成。模型可见服务状态控制工具仅调用前两类逻辑，不能获得 submit 秘密载荷。

本机 CLI 的参数只接受私有文件路径/挑战 ID/已配置目标标识；真实秘密从受保护文件或无回显终端读取，不作为 argv、stdout 或 tool result。应预设受信网关 URL，而非跟随模型返回的任意地址。仅合成回环可 HTTP，远程真实投递需单独获准且强制 TLS。响应确认 `binding_saved`、`binding_generation`、`discovery_status`，业务始终未自动执行。提交/回执生命周期设计与单实例重启语义未完成前，不宣传可用绑定功能。
