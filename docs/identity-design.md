# 身份、账号绑定与撤权设计提案

状态：总体设计提案；合成身份下的 [内存绑定与本地撤权内核](identity-kernel.md) 已实现，另有可选 [SQLite 持久化原型](persistence.md)；已新增可选本地本人绑定页面；真实身份、OAuth 网页授权、生产密钥管理和运维能力尚未实现。当前仍是回环入口、合成凭据的本地原型。本页供 [账号与认证 #5](https://github.com/yangkangbug/mcp-entry/issues/5)、[动态授权与运维 #6](https://github.com/yangkangbug/mcp-entry/issues/6) 评审，不构成生产安全或交付日期承诺。

## 产品目标与明确边界

用户为 MCP 客户端配置一个入口身份，再独立绑定自己的多个下游账号；不是所有用户共享一个入口账号。网页用于首次绑定、重新授权、查看状态与撤销，正常调用不要求频繁访问门户。

入口凭据、网页登录会话和下游凭据必须分离。入口 token、ID token、其他系统 token 不能透传为下游凭据。每次请求重新验证入口身份，MCP session ID 和工具参数不构成身份依据。接入外部 IdP，不新增自建密码库；网页能登录并不等于已支持 MCP 客户端认证。

用户只管理自己的绑定。支持 OAuth 的系统走受控授权流程；固定 token/API key 只在专用安全网页主动录入，不通过聊天或工具参数收集。保存后只展示掩码与状态，不提供明文回读。管理连接和策略不默认获得读取用户秘密的权限。

## 建议的最小对象模型

- Principal：内部稳定身份，映射受信 IdP 的 issuer 与 subject，不按邮箱或显示名猜测合并。
- Tenant：隔离域；成员关系由服务端可信来源确定，客户端不能自报租户取得权限。
- System：租户内固定下游连接、命名空间及认证配置，不等于下游账号。
- Binding：关联 tenant、principal、system 的授权记录，包含独立 ID、generation、状态及秘密引用。generation 用于拒绝旧回调、旧刷新结果和旧目录。

建议初版每用户每系统只有一个有效绑定。替换需显式操作并重新验证；多账号自动选择、共享应用身份暂不开放。客户端参数不得选择他人的绑定。不同用户即使绑定同一下游账号，也不共享授权记录、刷新结果或会话。

OAuth 绑定需保护 state、PKCE、适用时的 nonce、固定回调及 CSRF，校验发起身份和预期绑定版本。凭据、授权码及原始认证响应不得进入日志、工具目录或普通错误详情。

## 授权与撤权提案

list 与 call 共用一个默认拒绝的 evaluator：有效入口身份与租户成员、有效绑定、当前连接/工具策略、该绑定可见目录的交集。call 必须独立复核，不能把「曾在列表出现」当作授权。

建议单进程第一版将撤权和调用准入放在同一个原子边界：完成参数校验、等待限流及必要刷新后，再检查当前版本并取得 dispatch admission。撤权先提交则禁止新准入；等待中的请求醒来须重检。慢发现、旧 handler、旧回调和刷新结果均不得恢复已撤销权限。

准入先于撤权的请求已算在途，即使首个网络字节稍后才发送；只能尽力取消，不能承诺远端回滚或撤权后绝无旧请求字节。撤权前形成的列表也可能稍后抵达，但旧工具名不能获得新的调用权限。已确认结果与未知结果保持区分，不因刷新、限流或断连自动重放工具调用。多副本传播语义尚未设计，不宣称即时跨节点撤权。

## 实施状态与待决项

已实现合成身份下的内存对象、版本化授权、原子准入与局部目录失效，可选本地 SQLite 保存最新状态，未引入 OAuth 门户或生产密钥管理。回归覆盖跨租户隔离、直接调用越权、撤权与准入竞争、参数准备期间撤权、旧发现/刷新不能复活权限，以及现有协议与竞态回归。

之后再分别实现模拟外部身份提供方、安全绑定页面和持久化凭据生命周期。入口验证方式、缓存与撤销传播上限需要结合实际授权服务器能力决定，不统一预设在线 introspection 或禁用所有缓存。

状态存储与秘密存储应分离，元数据仅持必要引用；具体持久后端、密钥托管、恢复与审计故障策略仍待评审。审计只记录必要身份/绑定引用、版本、阶段和结果类别，不默认收集参数、结果或凭据。并发和速率限制需同时考虑用户、租户、连接及真实共享配额主体。

本提案不包含业务编排、业务任务轮询或真实写操作准入；完成账号绑定也不等于可生产部署。
