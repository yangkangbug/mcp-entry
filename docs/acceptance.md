# 验证记录

日期：2026-10-22。测试平台：Linux amd64，Go 1.27.3。依赖：官方 MCP Go SDK v1.7.0、jsonschema-go v0.4.3、modernc.org/sqlite v1.60.1。

## 覆盖范围

测试仅使用虚构用户、模拟凭证及回环 MCP 服务。

- 配置读取、系统命名空间、独立工具授权、身份和下游凭证隔离。
- 异构输入/输出 schema 与元数据、分页、目录更新和单系统失败隔离。
- 重复/恶意工具名、无效 schema、引用和 header 映射限制，以及普通同名数据的兼容性。
- 响应体、工具数量和分页边界；拒绝重定向和非法地址。
- 未发现或未授权工具不可直接调用；工具失败不自动重试。
- 不发布未实现的 resources、prompts 或 completions 能力。

## 有状态会话清理回归

此前，SDK 的同步 session DELETE 使用独立连接上下文，可能超过工具调用或发现预算。现在每个下游连接的 HTTP 请求、响应读取和清理共享操作截止时间/取消信号。

验证重点：
- 慢 DELETE 不突破调用方截止时间或单系统发现预算。
- 调用前取消不发起下游请求；操作中取消终止请求且不重试。
- 已确认的工具成功不会因随后清理失败而改成未知结果。
- 完整校验的目录可以在仅清理阶段超时后发布；列表阶段中断不发布目录。
- 取消后的活动请求会释放，响应关闭和传输错误会释放请求上下文。

有状态 JSON 清理回归与 SSE 响应取消回归分别验证请求释放。SSE 恢复未启用，不将断流后自动恢复计为已验证能力。

远端未确认 DELETE 时，不声称远端 session 已删除。当前保证是本地操作有界、可取消且不因清理重复业务调用。

## 工具契约与协议回归

契约与传输回归位于 `contract_test.go` 与 `protocol_test.go`，不增加业务编排或新的认证模式。

- 三个合成服务分别实现同步查询、显式确认写入和业务提交/查询；实际写入仅为测试内存计数。
- 比较完整工具定义及官方 SDK 直连结果，覆盖 annotations、icons、schema、工具/结果 `_meta`、content、structuredContent、isError 和 SDK 增补的结果字段。
- 默认值与 confirm 不自动填充；业务 ID、游标和幂等键保持不变。跨用户任务访问由模拟下游依据实际凭证拒绝，伪造参数身份无效。
- accepted/running/completed 和业务失败按下游数据保留；丢失提交响应后不重放、不自动查询，调用方仍可显式查询状态。
- 下游现代协议 2026-07-28 使用官方 SDK 验证 JSON/SSE 等价；2025-03-26、2025-06-18、2025-11-25 使用合成有状态服务强制 initialize 协商，校验实际版本头和 session ID。
- 入口亦验证三个 2025 版本的初始化、列举和调用；覆盖 modern discover 不支持及 HTTP 404 时的初始化回退。回退不重复 tools/call。
- SSE 结果前取消、确认结果后清理取消、截断/断连（有/无事件 ID）均有回归；断流不重放工具、不发起 GET 恢复。
- JSON/SSE 超大响应及由许多小注释组成的累计超限 SSE 均失败关闭；并发连接维持用户凭证隔离。

2024-11-05 早于 Streamable HTTP，不属于本传输矩阵。测试不表示已完成旧 HTTP+SSE、独立 GET SSE、事件恢复、外部 HTTPS、生产认证模式或完整 MCP 一致性验证。业务错误和传输未知结果是不同语义，详见 [兼容性边界](compatibility.md)。

## 有界同文档引用回归

- 输入/输出原始 schema 保留；支持的 `$defs`、definitions、转义/百分号片段指针及布尔目标按验证器语义工作。
- draft-07 与 2020-12 的引用同级约束行为分别验证；嵌套参数错误、参数深度/节点/工作量超限在连接下游之前拒绝。
- 根/嵌套/未使用定义中的环、指数级无环重复引用、非法指针、普通数据目标、外部/动态引用、含引用时的 ID/嵌套 dialect 变化均被拒绝。
- 节点、引用、原始深度、展开深度/工作量及参数预算有包含边界与越界用例；共享后缀不绕过展开深度限制。
- 外部引用目标为计数用模拟 HTTP 服务，断言零访问；发现失败清除对应系统旧目录，健康系统仍可调用。
- schema/data 同名关键字保持区别；普通 literal 数据不被当成引用或传输指令。大小写/Unicode 折叠别名与混合键冲突被拒绝，避免 typed 解码绕过原始 schema 检查。

本阶段不实现递归 schema、动态/外部引用、远程 schema 缓存或硬性 CPU 截止时间，详见 [支持子集与资源准入](schema-references.md)。

## 下游认证头回归

- 默认/显式 Bearer、raw Authorization、API-key header 均使用按用户/系统选择的虚构凭证；发现和调用保持选择一致。已补充 raw/API-key 独立有状态清理回归：initialize、tools/list、tools/call、DELETE 使用精确的同一凭据，覆盖并发身份/session 隔离、调用方截止时间和固定发现预算；已确认结果不被清理取消改写，不重复业务调用。
- raw/API-key 凭证值原样保留，不能由普通参数或 schema 覆盖；不同用户和系统并发调用不串用凭证。
- 非法模式、header 名、保留头、控制字符、非 ASCII、首尾空格及非法 Bearer token 拒绝。缺失凭证不回退到其他用户或入口凭证。
- 认证失败清除对应目录且错误不暴露凭证；不重试、不切换认证方式。
- 混合大小写的重复认证头被覆盖/清除，原请求不被修改。

认证头适配不表示已具备可信入口认证、凭证库或生产网络能力，配置及保留名单边界见 [下游凭证请求头](downstream-auth.md)。

## 合成身份与动态撤权回归

- 同名 principal 在不同 tenant 的绑定、策略、目录与凭据隔离；重复身份组合拒绝。
- 绑定替换/撤销、策略更新和禁用使用预期版本比较；失败不改变状态，元数据不回读凭据或共享可变切片。
- 参数准备期间撤权阻止最终准入；已准入请求尽力取消，未知结果不重放，已确认结果不因清理期间撤权丢失。
- 慢发现与恢复绑定交错不恢复旧目录；受影响系统局部失效，其他系统保持可用。
- 已捕获的内部 SDK handler、旧客户端连接及 session ID 不能绕过新策略、绑定代次或禁用状态。
- 并发顺序用通道控制，定向竞态测试重复 10 次通过；未引入真实限流队列，不将参数准备竞态称为排队限流验证。

范围与重启语义见 [内存身份与撤权内核](identity-kernel.md)。

## 持久化与恢复回归

- 显式初始化/重开；缺失、空文件、损坏、错误 key、非法 key 长度及拓扑/token 变化均失败关闭。
- 重启保持绑定 ID/代次、策略版本、撤权和禁用；过时配置不能重导入旧权限，工具目录需重新发现。
- 数据库和侧文件不出现虚构凭据明文；删除记录、修改元数据和替换跨身份密文均拒绝恢复。
- 最后一个元数据更新 SQL 由测试触发器强制失败，验证前序身份/绑定写入全部回滚；实例停止准入，重新打开读取已提交状态。
- 并发 CAS、Close 竞争与发现取消保持失败关闭；独立进程竞争所有权被拒绝，持有者被 SIGKILL 后可恢复已提交撤权。
- 持久化定向 race 回归重复 3 次通过。进程终止不是断电/磁盘故障模拟；没有验证所有文件系统或平台。

已有合成测试下的离线 key 轮换和审计检查点归档；完整旧备份的新鲜度证明、生产恢复流程及完整审计覆盖仍未实现。入口 bearer token 摘要不是生产密码存储方案，固定测试 key 不可用于真实凭据；详见 [存储与恢复边界](persistence.md)。

## 可执行入口与客户端回归

- CLI 标志组合在 I/O 前校验，非法输入不回显疑似 key；文件/stdin 精确有界读取，拒绝不安全权限、符号链接及错误长度。
- 真正的 gateway 子进程通过官方 Go SDK 完成双用户、双下游发现/调用、SIGTERM 关闭、持久重开及离线撤权/禁用；错误 key/损坏数据库不会打开监听。SDK 覆盖隐藏工具直接调用拒绝。
- 子进程 E2E 连续重复 5 次及 race 测试通过。子进程二进制按正常模式构建；race 检查覆盖测试驱动和完整库套件，不宣称子进程也被 race 插桩。
- 官方 MCP Inspector CLI 2.12.0 独立执行 modern/legacy 两种 protocol-era，验证差异化发现/调用及重启后的撤权/禁用；工具返回的身份、系统、消息保持一致。未捕获具体协商版本，未验证 GUI。
- Inspector 对隐藏/撤销工具的 tool_not_found 是客户端发现预检查；禁用身份返回 auth_required。此证据不替代 SDK 的直接越权调用测试，绑定更新、有效期及重新绑定已由后续集成验收覆盖。

运行步骤见 [本地预览](cli-preview.md)，没有实际账号或真实下游。

## 验证边界

未实现或未验证生产 OAuth、真实账号网页绑定、生产凭证库/密钥轮换与安全备份恢复、管理界面、真实业务系统及写操作、生产部署或完整 MCP 一致性认证。schema 校验不是恶意内容净化或完整 CPU 隔离，不应信任下游描述、注解或返回内容。

## 本人绑定与受控网络集成

- 真实 TLS 下游经 New 的不可变网络策略执行定向发现和调用；调用方随后修改原配置不会改变目标、允许列表或 CA。
- 入口/绑定过期拒绝、有效期持久恢复与篡改拒绝、v1 明确拒绝；同一绑定并发发现取消旧操作，过时结果不清除新目录。
- 本人 API 的同源/身份隔离、重复/未知 JSON 字段、CAS、慢请求体期间身份禁用/过期的最终准入回归；脚本语法检查通过。
- 官方 MCP Inspector 2.12.0 的 modern 和 legacy 两种 protocol-era 均通过实际网关进程及合成 HTTPS 下游：本人替换凭据后观察到新凭据、定向刷新、过期隐藏/拒绝、重新绑定、重启保持代次/有效期/新绑定，以及持久撤销和禁用。
- Inspector 同时验证 401、403、429、503 和连接中断的固定错误类别、未知结果/不重试提示、每次失败 tools/call 仅发送一次且不暴露提供方错误体。正常工具结果仍保持原样。

这些是独立 CLI 客户端和 HTTP/协议测试，不是实际浏览器交互或 GUI MCP 客户端验证。没有真实用户账号、生产下游或真实写操作。完整旧数据库备份的反回滚、生产密钥轮换、完整审计覆盖与入口负载治理仍未完成。
