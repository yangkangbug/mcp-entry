# 架构与威胁模型

## 请求路径

1. HTTP 边界拒绝浏览器 Origin，并验证固定演示 bearer token。
2. 将身份映射到独立、只包含获准工具的 MCP server。入口为 stateless 模式，不接受会话 ID 作为身份凭证。
3. SDK 解析 MCP 并校验工具 schema。网关再次按用户和完整工具名检查权限。
4. 从不可变配置取出系统、下游地址和真实下游工具名。客户端参数不能改变这些字段。
5. 按用户和系统选择模拟凭证，建立独立的官方 SDK 客户端，通过 Streamable HTTP 调用一次。
6. 传输错误对外脱敏。下游正常工具结果仍是外部不可信内容。

## 信任边界

- 调用方不可信：不能用隐藏工具名、伪造前缀、参数或其他用户会话获得权限。
- 下游不可信：不能动态发布工具覆盖本地路由，不能通过重定向接收跨目标凭证。
- 配置由本机操作者管理，启动后复制为只读；当前不支持运行时管理 API。
- 模拟 token 明文保存在示例源代码中，任何人都知道；此实现没有生产认证强度。
- 本机其他进程可使用公开演示 token。回环绑定只是减少网络暴露，不是完整权限隔离。

## 主要保护与限制

- 默认拒绝无身份、未知工具、未授权工具和缺失系统凭证。
- 工具命名规则为 `system__tool`，拒绝分隔符歧义与重复名称。
- 每个 HTTP 请求重新鉴别身份。无共享的下游用户 session 或 cookie jar。
- HTTP 客户端拒绝所有重定向；只向静态回环目标发送对应模拟凭证。
- 入口请求体限制 64 KiB，下游单个 HTTP 响应限制 1 MiB；下游调用有 10 秒上下文期限，HTTP 客户端有 12 秒期限。
- SDK 重连关闭，网关没有应用层工具重试。SDK 初始化时可能进行协议发现与旧版 initialize 回退；这不代表重复执行 tools/call。不提供 exactly-once 保证；遇到未知结果时需业务幂等键或人工确认。
- 不记录请求头、凭证或工具参数。不实现生产审计；真实部署前应设计脱敏审计。
- 本原型只转发 echo，没有真实写操作。不能把演示测试当作真实业务副作用的保证。

## 后续实现顺序

1. 确定企业身份、租户和 OAuth/OIDC 信任模型；分离入口 token 与下游 token，禁止透传。
2. 完成安全的浏览器账号绑定：state、PKCE、nonce、回调白名单、重放防护和 CSRF 防护。
3. 增加持久化凭证库与密钥管理、轮换、撤销和最小权限访问。
4. 实现受权限控制的管理界面、策略变更审计，以及每请求动态撤权。
5. 接入一个真实只读系统，验证 schema、超时、限流和恶意返回值边界。
6. 只有经过单独审核和幂等设计，才启用真实写操作。
