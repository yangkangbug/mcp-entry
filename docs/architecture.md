# 架构与威胁模型

## 模块

- cmd/demo：显式启动两个虚构 MCP 下游并运行发现演示。
- cmd/gateway：读取配置，只启动入口；不启动任何下游。
- internal/gateway/config.go：受限 JSON 配置与连接/身份/策略校验。
- internal/gateway/persistence.go：可选 SQLite 单实例存储、凭据加密、状态完整性与失败关闭。
- internal/gateway/identity.go：合成身份、内存绑定与策略版本、受信进程内变更和本地撤权。
- internal/gateway/gateway.go：发现、按用户的目录快照、授权、schema 校验与代理。
- internal/mock：仅用于演示及测试的 MCP 服务。

仍然是模块化单体，不引入数据库、消息队列或额外代理组件。

## 发现与目录

1. 读取配置并复制为不可变系统连接与入口身份，并初始化内存绑定和版本化白名单；启动时尚无任何可调用工具。
2. 对每个用户分别连接获准系统，使用该用户该系统的下游 token，不使用共享管理员 token。
3. 遍历标准 tools/list 分页。检查完整系统目录后再发布，不发布半页结果。
4. 为原工具名加固定系统前缀，保留 SDK 支持的工具元数据及 schema。名称和参数不能改变系统地址。
5. 发布「该用户下游目录 ∩ 本地工具白名单」的独立快照。
6. 同一个系统可能对不同用户公布不同工具/schema；这些结果绝不互相复用。

系统名或工具名不能包含 `__`；公开完整工具名必须匹配 ASCII `[A-Za-z0-9_.-]` 且不超过 128 字符。同一系统重复名称、非法名称、分页循环或 schema 错误会使该用户的整个系统目录不可用，而不是静默覆盖。

Refresh 按确定顺序执行，并原子替换整个目录。失败系统不保留旧工具；健康系统保留这次成功发现的结果。正在执行的调用可完成，刷新不保证中断已发出的业务请求。当前命令只在启动时调用 Refresh，配置不可热改，没有自动刷新或远程管理入口。受信任的进程内方法支持绑定替换/撤销、策略更新和身份禁用，详见 [内核语义](identity-kernel.md)。

## 调用与身份边界

每个 HTTP 请求验证固定演示 bearer token。stateless 入口不将 MCP session ID 当身份。用户服务端只注册其当前目录的工具；旧 handler 的列表仍重新检查当前权限和目录版本。Call 路径在参数校验后最终复核白名单、身份状态、绑定代次、策略版本及目录版本，再原子登记在途操作。

网关使用发现时的输入 schema 校验 JSON 参数，不应用默认值或改写参数。没有参数的工具允许省略 arguments。转发恢复原始工具名，使用用户专属的临时 MCP 客户端连接；不共享用户会话或 cookie jar。输出 schema 原样公布，返回值原样转发，不宣称替下游执行输出契约校验。

## 有界失败与攻击面

- 配置限制 256 KiB、16 个系统、64 个用户；每用户白名单最多 2048 个名称。
- 每用户每系统发现最多 16 页、128 个工具、1 MiB 工具定义总量；单工具定义最多 64 KiB。
- 入口请求体和 Call 参数最多 64 KiB；每次下游 HTTP 响应最多 1 MiB；分页 cursor 最多 4096 字节。
- 单系统发现 5 秒；命令启动发现总共 30 秒；工具调用上下文 10 秒，HTTP 客户端 12 秒。每个连接的 HTTP 请求、响应读取及有状态 session DELETE 清理都受同一个操作上下文约束，更早的调用方截止时间或取消同样生效。
- schema 原始深度最多 32；仅支持验证器支持的 JSON Schema draft-07/2020-12；输入根必须显式为 object。仅接受有界、无环的同文档 JSON Pointer 引用；拒绝外部、动态及递归引用，不下载外部 schema。详见 [引用准入与限制](schema-references.md)。同步 schema 验证受节点/深度/工作量准入约束，不是可由操作 deadline 强制中断的 CPU 隔离。
- 暂不支持 schema 位置的 x-mcp-header 参数映射，发现时直接拒绝；普通属性名及 example/default 数据中的同名键不是映射，允许保留。此限制避免不可信 schema 改变传输行为。复杂扩展兼容性不是本阶段目标。
- 只接受字面回环 HTTP 下游地址，所有 HTTP 重定向被拒绝；入口仅绑定回环且拒绝所有 Origin 浏览器请求。
- SDK 重连及自动 MultiRoundTrip 均关闭，无应用层工具重试。SDK 的 server/discover 到旧版 initialize 回退属于协议初始化，不是重复 tools/call。
- session 清理同步执行，不另起后台任务，也不重试工具。若已收到明确工具结果，之后的 DELETE 超时或取消不会把成功改写成未知结果；尚未收到明确结果的中断仍按未知结果处理。
- 发现只有完整获取并校验的系统目录才可发布；若仅在后续清理阶段超时，保留完整目录。列表获取/校验阶段中断则不发布该系统。远端拒绝或未确认 DELETE 时，不保证远端 session 已删除；保证本地请求可取消并释放资源。
- 网络故障可能导致调用结果未知，不提供 exactly-once；真实写操作需要另行设计幂等键和确认策略。
- 诊断只报告用户/系统和固定失败类别，不打印 token、原始下游错误或参数。工具描述、注解和正常返回值仍不可信，可能含恶意内容，不是安全指令。

## 明确不保证

公开的静态 token、回环监听和内存快照不是生产身份验证、租户隔离或持久化凭证管理。任何本机进程都能使用演示 token。配置必须仅使用虚构测试凭证；不要填写真实账号数据。该实现不提供公网安全、完整审计、生产限流、恶意 schema 的完整 CPU 隔离或全协议一致性认证。

## 后续边界

1. 为连接健康、目录更新和配置错误提供受控可观测性，不扩大数据共享范围。
2. 明确 OAuth/OIDC、租户与账号绑定信任模型，设计 state、PKCE、nonce、回调白名单和 CSRF 防护。
3. 单独实现持久化凭证库、密钥管理、轮换、撤销与最小权限。
4. 再增加经过授权的管理界面与持久化、多副本策略撤销。
5. 接入真实只读系统后评估 schema、超时、限流；只有单独审核与幂等设计后才启用真实写操作。

## 下游认证头

系统配置选择 Bearer（默认）、raw Authorization 或受限的 API-key header，凭证仍严格按用户与系统选择。协议/路由/代理/Cookie/session/转发身份等已知保留头不可配置为 API-key header；参数与 schema 不参与认证头选择。发现、调用和清理使用同一选择，重定向仍拒绝。此适配不引入新的入口身份或凭证持久化机制，细则与虚构配置见 [下游凭证请求头](downstream-auth.md)。

## 可选持久化

NewPersistent 为库级显式选择，默认命令仍使用 New 的内存模式。候选授权状态提交到 SQLite 后才发布；写失败关闭准入，重开不重新导入旧策略或凭据。入口只存验证摘要，下游凭据使用独立外部密钥派生的 AEAD 加密，元数据仍可读。单实例所有权、关闭、初始化和旧备份风险见 [存储说明](persistence.md)。
