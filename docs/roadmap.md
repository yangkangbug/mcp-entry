# 产品方向与 v0.1 内部试点路线图

mcp-entry 的目标是轻量、通用、基于 MCP 标准的 Go 统一入口：用户配置一个入口身份，再独立绑定自己的多个下游账号，通过同一个入口发现和调用获准工具。不为特定客户端另造协议，也不承担业务编排。

本页定义开发顺序与验收条件，不表示未来能力已经实现，不承诺日期、吞吐量或生产 SLA。Issue 状态核对于 2026-10-22；设计提案不等于实现。

## 目标与推进边界

v0.1 面向**单实例、一个受信管理域、受控网络内的只读试点**，不是任意用户/下游可接入的公网服务，也不是通用生产就绪承诺。保留官方 Go SDK 与 Streamable HTTP，只代理已声明支持的工具发现和调用子集。

按两个可验收的结果推进，不把所有试点门槛压到第一步：

1. **先跑通可安装的预览闭环：**在干净环境按说明启动网关，以实际 MCP 客户端、两个合成用户和两个模拟下游完成差异化列举/调用、绑定替换、撤权、重启与故障验证。
2. **再进入单独批准的只读试点：**安全门槛通过后，选定真实入口身份提供方、实际 MCP 客户端和至少一个真实或受控预发布只读下游，用隔离测试账号验证完整路径。未授权或未验证时保持预览标识，不能宣称真实接入已跑通。

管理者配置固定下游；用户不能提交任意地址、认证头或他人的绑定。每用户每系统最多一个有效绑定。只读范围由管理者审核的显式工具白名单和下游只读账号权限共同限定，不能依赖不可信的 `readOnlyHint`。真实账号/系统联调需另行授权，本路线图不授予该权限。

## 已完成：可复用的原型基础

- 配置驱动连接、标准 `tools/list` 分页发现、`系统名__原工具名` 映射和固定路由；按用户发布「下游实际可见 ∩ 本地明确授权」目录，调用独立授权。
- 每用户/系统凭据隔离；Bearer、raw Authorization、受限 API-key header；工具 schema、受支持元数据及结果语义保留，有界无环同文档引用。
- 合成 tenant/principal 下的内存绑定代次、策略版本、目录失效、原子调用准入与本地动态撤权。
- 会话清理预算、JSON/SSE、异构工具和异步业务字段透明转发的模拟回归，以及现有 CI。

上述能力只验证过回环模拟服务、合成身份与虚构凭据。默认配置仍使用演示 token；默认 CLI 的撤权只在内存中，重启可能恢复旧配置凭据。已新增可选 SQLite 持久化原型及显式持久 CLI/离线操作者命令，保存加密下游凭据、入口验证摘要和最新授权状态。已增加显式本人绑定预览、有效期与定向刷新，以及受控 HTTPS 和脱敏失败分类。真实身份、OAuth 安全绑定、生产密钥管理与安全备份恢复、完整审计覆盖和入口负载治理尚未完成；已有事务性元数据审计与出站并发/速率限制。现有管理方法只供受信任的进程内调用，不能直接暴露为管理 API。

依据：[README](../README.md)、[内存身份与撤权内核](identity-kernel.md)、[身份设计提案](identity-design.md)、[验证记录](acceptance.md)。

## 必须交付：按完整路径推进

优先 S1 持久化/恢复；S2 安全网络/诊断是独立并行线，不阻塞 S1 的合成测试。S3 先在模拟环境跑通；真实试点前 S1–S4 的安全门槛必须全部通过。S5 从最小运行说明开始，最后汇总端到端证据。

### S1：绑定、策略和撤权跨重启成立（#5、#6）

进度：已实现 [单实例持久化原型](persistence.md)、[可运行 CLI 预览](cli-preview.md) 和 [离线维护](maintenance.md)，包括显式初始化/重开、事务后发布、入口凭据替换/撤销、认证格式迁移及根密钥轮换；合成提交故障与重开恢复已验收。真实密钥提供方及生产备份恢复仍待验证；完整旧数据库的回滚不能仅凭同一数据库与密钥检测。

- 选择单实例持久后端，保存稳定身份/绑定标识、代次、策略版本及禁用/撤权状态；提交可靠落盘后才能报告成功，不能重启后重新导入旧权限。
- 下游凭据加密存储，密钥与数据分离；入口 token 可用摘要验证，不保存可回读明文。定义密钥提供/轮换、备份恢复和最小访问权限；存储或密钥不可用时拒绝操作，不回退演示身份。
- **验收：**替换绑定、撤权、禁用和缩减策略后重启，旧凭据/目录/版本不能调用；覆盖崩溃、提交失败、密钥缺失/错误、轮换和备份恢复。不能证明撤权状态的恢复先隔离停用，防止旧备份复活权限；日志、状态和备份不得出现明文秘密。保留准入与撤权的 race 回归。

撤权只阻止提交后的新准入，并尽力取消在途工作；不能保证远端回滚，不承诺跨节点即时撤权。

### S2：受控 HTTPS 连接与可诊断失败（#2）

进度：已实现固定下游端点、全量 DNS 地址检查与数值地址拨号、显式 IP 允许列表、验证 TLS、拒绝代理/重定向及脱敏失败分类，并通过合成 TLS 和实际 Inspector CLI 回归。入口默认回环 HTTP，已增加显式远程合成测试 HTTP/HTTPS 开关；生产证书运维及反向代理信任边界尚未完成。

- 默认继续回环演示。试点须显式启用且配置缺失即拒绝启动；入口及受控下游使用验证证书的 HTTPS。允许受信反向代理终止 TLS，但禁止绕过代理访问网关或信任任意客户端身份头；明确 Host/Origin 和可信代理边界。
- 端点允许列表与出口限制覆盖 DNS 解析、实际拨号和重定向；内网地址只能显式授权，拒绝 URL 用户信息、越权目标和跨目标转发凭据。定义代理环境变量、Cookie、连接池/复用行为，参数/schema 不得改变认证或目标。
- 明确发现、调用和清理预算，清理仍受父操作总预算约束。脱敏分类区分入口认证、下游认证拒绝、权限不足、限流、服务/传输故障、工具错误和业务失败；下游 401 不冒充入口 401，也不能独自证明过期/撤销。
- **验收：**合成 TLS/DNS 夹具覆盖证书失败、未授权地址及 DNS 变化、重定向、代理绕行、恶意 Host/Origin、三种认证头和凭据隔离；JSON/SSE 错误语义一致，无秘密泄漏。已确认结果不因清理失败改写，未知结果不自动重放。

### S3：最小可用的个人账号接入（#5、#6）

进度：已实现显式开启的本地本人绑定页面/API，使用预配置的有限期入口凭据，支持仅本人替换、撤销、过期提示与定向刷新；没有 token 颁发、OAuth 或账号注册。Inspector CLI 验证替换、过期、重新绑定及重启持久性；浏览器交互未完成实测。

- 选择一种可信入口身份方案及实际 MCP 客户端认证组合，不自建密码系统，不要求完整企业 OIDC 平台；网页登录成功不等于 MCP 客户端认证成功。
- 提供绑定、掩码/状态查看、替换、解绑及目录刷新路径：可用本人安全页面，或经过认证且获得明确授权的操作者配置流程，不要求完整自助门户。入口身份、网页会话和下游凭据分离，管理员不能默认读取用户秘密。
- 优先完成固定 token/API-key 的一个端到端绑定路径；秘密只从专用安全页面或受保护注入路径提供，不进工具参数、聊天、命令历史或日志。入口凭据支持过期、轮换、撤销；用户变更后无需靠重启刷新目录。
- 实施所选路径适用的会话、CSRF/重放和对象归属保护。若启用 OAuth，则 state、PKCE、适用的 nonce、固定回调和按绑定隔离的并发刷新必须验收，不要求所有 OAuth 提供方。
- **验收：**模拟身份提供方下两用户从登录到绑定两个下游、客户端连接、差异化列举/调用、替换、解绑、禁用完整通过；覆盖越权管理、重复/过期操作、身份服务故障、认证失败与重新授权。429/5xx/超时不误记为永久失效或自动解绑，单个绑定故障不影响其他用户/健康绑定，旧刷新不能复活权限。

### S4：审计与有界负载（#2、#6）

部分完成：[事务性元数据审计与零队列出站限额](audit-limits.md)、离线导出及检查点归档。已增加独立的入口限额、CLI 连接/读取预算及固定空间进程内拒绝摘要；完整持久请求审计、生产入口治理与代表性负载基准仍未完成。

- 记录必要身份/绑定引用、工具、策略版本、关联请求、阶段、耗时和结果类别，覆盖调用、绑定、撤权和管理动作；默认不采集原始参数、完整结果、认证头或秘密。定义审计访问、保留、清理及写入失败策略，不能无声丢失必需管理审计或放宽授权。
- 为调用、发现、刷新设置并发/速率、排队长度/等待时间及请求/响应规模上限，覆盖用户、连接和真实共享配额主体。排队后重检授权；超时/取消释放资源，过载明确拒绝，不无界堆积。
- **验收：**慢下游、持续过载、排队期间撤权、共享配额、审计不可用和取消清理测试通过；测试秘密不出现在审计/日志/客户端错误中，不串用身份，不自动重放调用。记录负载条件，不外推未测性能。结构化日志和受控运维命令即可，不要求管理大屏。

### S5：运行说明与端到端证据

- 先选一个实际环境，复用 Go 构建和 CI，提供最小构建/配置/启动说明，按首节定义先完成实际客户端加模拟下游的预览闭环；不先做多平台安装包、容器或发行自动化。
- 说明 HTTPS/代理、身份/密钥配置、绑定、撤权、刷新、故障定位和安全恢复；演示/试点配置分开。验证重启/恢复不恢复旧权限，必要时停服恢复，不承诺零停机或盲目回滚数据库。
- 格式、模块验证、普通/race 测试、vet、build 及声明的兼容性回归通过。记录准确版本和脱敏验收证据；安全门槛通过且另获授权后，再验证首节的实际只读试点。

**完成条件：**分别报告「预览闭环通过」与「获批准的内部只读试点通过」，不能混用。试点需 S1–S5 必需证据齐全、按说明可复现且限制明确，不等于公开发行或广泛生产准入。

## 暂缓与待决事项

- **开源维护先暂缓：**LICENSE、贡献指南、公开发布流程、多平台打包和完整升级支持待内部闭环跑通后再做。许可证尚未选定，不要求现在决定，不阻塞当前研发/内部试点；正式开源分发前须由所有者选定并核对依赖声明，公开代码不等于已有开源许可。
- **不纳入本版：**多实例/多地域 HA、跨节点即时撤权、复杂多租户门户、所有 OAuth 提供方、多账号自动选择、共享应用身份、任意远程地址、MCP 服务安装/托管/启停、Kubernetes、额外传输、resources/prompts/sampling/elicitation/任务扩展、递归/动态/外部 schema 引用及全协议认证。
- **不纳入本版：**真实写操作、业务任务轮询/幂等/跨系统事务及单一客户工作流特判；`task_id` 等按契约不透明转发，异步受理不等于业务成功。
- **进入相应实现前确定：**生产密钥提供与恢复策略（本地单实例状态后端已选 SQLite）、审计故障策略，以及首个部署环境/可信身份提供方/MCP 客户端组合。选型服务最小闭环；真实联调另行批准，许可/发行决策延后。

## 反馈原则

可复现的通用缺陷优先修复并补回归；配置问题通过校验/文档解决；适配需求先证明通用价值与可选边界，超范围需求记录证据而不直接扩大本轮范围。请提交最小复现、版本、预期/实际结果和脱敏日志，不提交真实 token、私人配置或客户数据。

离线维护已覆盖入口凭证替换/撤销、认证格式迁移与根密钥轮换；操作边界和未知提交结果处理见[维护说明](maintenance.md)。真实密钥提供方、备份新鲜度与实际只读试点仍需独立验收。
