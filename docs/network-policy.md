# 受控下游网络与失败分类

默认仍仅允许字面回环 HTTP 下游。每个系统可显式设置 network，启用固定端点的 HTTPS；隔离测试可再显式开启 allow_insecure_http，见 [远程测试](remote-testing.md)。测试只使用本地合成 TLS 服务；没有连接真实系统，也没有放开入口监听范围。

```json
{
  "name": "example",
  "endpoint": "https://mcp.example.test:8443/mcp",
  "network": {
    "allowed_ips": ["192.0.2.10"]
  }
}
```

这是格式示例，不是可运行的实际服务。`allowed_ips` 是精确 IP，不接受 CIDR；目标域名由管理员固定。省略 `trusted_ca_pem` 使用系统根证书；可在该字段提供 PEM 格式的专用 CA，此时仅使用配置的证书池。始终验证证书链与端点主机名，不提供跳过验证开关。

## 出口约束

- 受控端点固定 scheme、host、port 和路径；拒绝用户信息、查询参数、fragment、非规范/含转义路径及歧义主机形式。
- 每次新拨号检查全部 DNS 结果，任一地址不在精确允许列表即拒绝；仅向检查后的数值地址拨号，TLS 仍使用配置主机名验证。
- 私网地址只有显式允许才可用；拒绝未指定、多播、链路本地、已知云元数据地址和易混淆映射地址。静态保留地址规则不是所有网络服务的通用信任探测器。
- 不使用环境代理、Cookie jar 或 HTTP 连接复用；拒绝所有重定向，凭据不随目标变化转发。请求 Host 和 URL 也必须匹配固定端点。
- 连接配置与编译后的传输策略在 New 时复制；之后修改调用方配置不改变已建立的授权边界。工具名称、参数和 schema 不能指定网络目标或认证头。

管理员仍必须审核目标和本机 DNS/CA/网络配置，操作系统出口策略可作为额外防线。本原型不等于任意 URL 代理，可显式启用远程合成 MCP 测试入口，但不支持可信反向代理身份接入或生产网络部署。

## 安全错误类别

`DownstreamFailure` 只保存固定 code、phase、可用的 HTTP status 和 outcome_unknown，不保留原始 URL、响应体、请求头或底层错误。类别区分下游认证拒绝、权限不足、限流、服务不可用、超时、取消、传输及协议失败。缺乏证据时不能假定更具体原因；本地网络策略拒绝与重定向拒绝归入传输失败。

入口认证失败仍是入口 HTTP 401；下游 401/403 不冒充入口身份失败，不自动修改绑定状态。已确认的 MCP 工具结果，包括 isError 和业务字段，保持原样，不被网络分类器包装。正常工具内容也可能包含敏感或恶意数据，本分类器不净化业务内容。

工具发出后的失败可能具有未知结果，即使收到 HTTP 拒绝，也不推断无副作用。没有应用层自动工具重试、业务轮询或幂等编排。SDK 的现代 server/discover 到旧版 initialize 回退最多涉及协议握手请求，不是重复 tools/call。已确认结果不因清理失败改写。

发现、调用和清理仍共享原有操作预算。TLS/拨号与响应头有附加上限，不扩大父操作 deadline。测试包括 TLS 信任、IP/DNS 限制、代理/重定向拒绝、请求头隔离和真实 Inspector CLI 错误回归；不宣称完整 MCP 一致性或生产可用性认证。

明文下游仅在 network.allow_insecure_http=true 且配置精确允许 IP 时接受；所有地址防护保持不变。HTTP 与 trusted_ca_pem 组合拒绝；HTTPS 不因该标志绕过证书验证。默认无 network 的回环 HTTP 演示保持兼容。
