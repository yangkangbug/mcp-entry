# 单实例持久化与恢复

> 更新：持久管理端现支持[动态用户与入口凭据](managed-user-lifecycle.md)及[受控服务新增/超时应用](runtime-service-config.md)。运行注册表与原启动配置锚点有明确区别；不得用导出运行配置覆盖启动种子或重置数据库。

这是可选的单实例原型，仅用于本地合成身份和虚构凭据。默认 New、cmd/demo 和 cmd/gateway 仍使用内存模式，cmd/gateway 可显式通过 -db 和 key 文件/标准输入启用持久化，步骤见 [本地预览](cli-preview.md)。没有 token 颁发接口、真实密钥配置或生产账户接入。

## 保存什么

- SQLite 保存身份/绑定标识、绑定代次、策略版本、允许列表、入口/绑定有效期、禁用及撤销状态。
- 入口 token 仍由演示配置预先提供，不是网关颁发。数据库仅保存带用途区分的 SHA-256 验证摘要，网关复制的用户配置也不保留原 token。摘要不是密码哈希方案；未来生产 bearer token 必须具有足够随机熵，公开演示 token 不具备生产安全性。
- 下游凭据必须在调用时使用，因此用 AES-256-GCM 加密后存储，而不是单向哈希。随机 nonce 由 Go 标准库生成；附加认证数据绑定用户、租户、principal、系统、绑定 ID、代次和状态。
- 外部提供的 32 字节根密钥通过 HKDF-SHA256 分离派生加密与完整性密钥。全量规范化记录有 HMAC-SHA256 完整性校验，另有加密的密钥检查值；错密钥、行删除、字段或密文替换均拒绝恢复。

数据库不保存工具调用参数、结果或业务记录；新增有界的[元数据审计](audit-limits.md)。工具目录不持久化，重开后必须 Refresh。身份与策略元数据可直接读取，SQLite 文件并非整库加密。

## 明确初始化与重开

库接口为 NewPersistent(cfg Config, opts PersistenceOptions) (*Gateway, error)，opts 含 Path、Key、Initialize。Key 恰为 32 字节，调用方负责从数据库之外提供；本项目没有自动生成或托管真实密钥，离线轮换只经合成测试验证。

Initialize=true 只允许创建不存在的文件，使用排他创建与 0600 权限。它不会覆盖已有数据库。Initialize=false 只打开已有有效数据库；缺失、空文件、损坏、错误密钥、未知版本或不完整记录均返回 ErrStorage（版本不兼容细分为 ErrStorageVersion），不回退内存模式，也不自动重新导入配置。初始化中断留下的文件不会自动删除或重新初始化。

重开仍提供配置以确认不可变系统连接/认证模式与身份范围。拓扑不匹配会明确失败。入口 token、有效期、策略和下游凭据只是首次初始化种子；重开忽略这些种子，使用经过认证的数据库状态，旧配置不能恢复撤销的权限或延长有效期。身份、连接及容量配置仍须通过格式校验。

例如，在测试中使用 t.TempDir 下的数据库路径和明确标记为虚构的固定 32 字节测试 key，首次 Initialize=true；关闭后以相同路径/key 和 Initialize=false 重开。不要将该测试方式当作生产密钥管理方法，也不要把真实 key 写进配置或仓库。

## 提交、关闭与恢复边界

变更先构建独立候选状态，在同一 SQLite 事务中写入身份、绑定和全量完整性校验，提交成功后才发布内存状态、失效目录并取消受影响操作。提交结果未知或任意持久化写失败时返回 ErrStorage，并关闭整个实例的准入，不能继续用旧内存授权；需重新打开以读取实际已提交状态。不能因未知结果直接假设成功或重试业务调用。

Gateway.Close 幂等，停止新准入、尽力取消在途操作并释放存储。它不保证下游回滚，也不保证已由调用方持有的配置、字符串或密钥被安全擦除。已经确认的业务结果与清理失败仍保持区别。

使用单个固定生命周期 sql.Conn、SQLite EXCLUSIVE 锁、DELETE 回滚日志和 FULL 同步。只允许一个实例持有数据库，另一进程打开会失败；退出或崩溃后由 SQLite 处理锁释放和事务恢复。不要手动删除正在使用的数据库或日志文件。

前提是可信、私有、稳定路径的本地目录，且文件系统正确支持 SQLite 锁和同步。实现拒绝最终路径为符号链接、非普通文件或组/其他用户可读写的数据库，但不能防御有目录写权限的攻击者替换路径，也不保证网络文件系统或所有平台的行为。当前验证平台见 [验证记录](acceptance.md)。

完整性认证不能识别“完整但较旧”的数据库副本。同一密钥下恢复旧备份可能恢复旧权限；本阶段没有外部单调计数、备份新鲜度证明或自动安全恢复流程。未经确认的备份不得直接作为可服务状态恢复。密钥丢失不可恢复。已有离线根密钥轮换，但生产密钥管理、安全备份恢复和多实例协调尚未实现。

## 依赖

SQLite 驱动固定为 [modernc.org/sqlite v1.60.1](https://pkg.go.dev/modernc.org/sqlite@v1.60.1)，无 cgo；它要求 Go 1.26 或更新版本。事务锁定与同步行为依据 [SQLite PRAGMA 文档](https://www.sqlite.org/pragma.html)。加密与 HKDF 使用 Go 标准库，依赖完整性由 go.sum 与 go mod verify 检查。

## 存储版本与有效期

当前格式为 v4，包含入口凭证代次/撤销状态、经过认证的审计链、归档检查点与头部。入口有效期参与状态完整性认证，绑定有效期同时参与完整性认证和 AEAD 附加认证数据；重开后仍执行过期拒绝。入口有效期以存储为准，不能通过编辑配置延长；离线更新必须替换 token 并通过独立入口代次 CAS。

正常服务明确拒绝旧格式，不会自动升级。离线 -operation migrate 可认证并事务升级 v2/v3 到 v4，保留策略、绑定代次/撤销、有效期和既有审计；v1 仍不支持。迁移不补发有效期，也不从配置重新导入权限。旧格式没有认证过的 token 强度标记，因此迁移后保守标记为弱，须离线替换入口 token 后才能启用要求强身份的远程/account 模式。失败不删除或重新初始化原文件。详见[离线维护](maintenance.md)。
